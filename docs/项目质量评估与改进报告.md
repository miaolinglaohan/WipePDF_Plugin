# WipePDF 插件项目质量评估与改进报告

日期：2026-09-19  
性质：基于当前工作区的代码、文档与本地 SDK 说明进行的改进设计；不是已实施的修复说明。  
本次变更范围：仅新增本报告，不修改源代码、构建脚本、安装脚本和现有说明文件。

## 1. 结论与项目定位

项目已经具备 Acrobat 原生插件的基本功能闭环：加载与菜单注册、当前文档清理、手动点选、全文匹配计数、批量文件处理、页面分析和规则设置。模块划分清晰，能够作为继续改进的基础。

当前最大问题不是水印识别种类不足，而是“识别对象、删除范围、预览范围、保存与恢复”之间缺少可靠的一致性保障。现有实现不能支撑 README 中“绝不触碰其他内容”“无损清除”等绝对承诺。

建议将项目定位明确为：**由保守自动识别与人工精准选择组成的 PDF 水印对象清理工具。** 它直接修改 PDF 对象，不是对扫描图像进行像素修复的工具。水印已与扫描正文融合在同一张图片中的情况，应明确提示当前能力边界，不能通过删除整张扫描图来完成清理。

改进优先顺序：先控制误删和保存风险，再提升人工点选精度，随后完善自动识别、性能和工程质量。

## 2. 必须遵循的两条产品原则

### 2.1 自动一键删除：可以保守，优先不破坏文档内容

用户要求：自动清理允许漏删，但应尽量不误删正文及其他有效内容。测试中出现过“删除了看不见的东西，且确定不是可视水印对象”的现象，因此不能再将“对象不可见”直接等同于“对象无用”或“对象是水印”。

具体要求：

- 自动清理的默认目标是证据充分、可独立删除的水印对象。
- 不把透明度为零、不可见文字、普通链接、页面底部位置、重复出现、字号大等单一特征当作自动删除依据。
- 正文之外的有效内容也必须保护，包括 OCR 搜索层、可复制文字、目录跳转、参考链接、表单、批注、图层及阅读辅助结构。
- 证据不足时保留对象；可以报告“疑似水印”，引导用户使用点选功能。
- 每个拟删除对象都必须可以解释：在哪一页、是什么、为何判定为水印、将影响什么。
- “一键”表示流程简便，不表示省略必要的备份、范围审查与结果验证。

自动模式的优化方向是降低误删率，不能以删除数量多作为效果好的主要指标。

### 2.2 点击删除同款：依靠人工判断，尽可能精准

用户要求：有人参与选择和检查，可以协助判断效果，因此应尽可能精确识别点击目标及其同款对象。

具体要求：

- 先准确选中用户点击的可视对象，再识别其他页面的同款。
- 人工选择只授权处理该目标及用户确认的候选，不授权同时执行其他自动规则。
- 默认“同款”应有内容身份依据，不能仅依据相同尺寸、位置或类型。
- 用户应看到目标高亮、候选分布、差异和预计删除范围，并可排除单个候选或页面。
- 扩大匹配范围是明确的用户操作，例如允许缩放、旋转或位置变化；不能隐式放宽。
- 效果应能够在保存前检查，并具有明确的撤销或恢复途径。

人工参与可以处理不确定性，但不能替代算法正确性，也不能把“用户已经确认”作为误删非目标内容的理由。

### 2.3 两种模式的边界

| 维度 | 自动一键删除 | 人工点击删除同款 |
| --- | --- | --- |
| 目标来源 | 高置信证据产生候选 | 用户选定目标产生候选 |
| 默认倾向 | 宁可不删 | 精确识别目标，完整展示候选 |
| 不确定对象 | 保留并说明 | 展示给用户，默认不勾选低置信候选 |
| 匹配方式 | 组合证据及保护条件 | 内容身份为主，几何和样式为辅 |
| 不可见对象 | 默认不删 | 普通可视点选不应自动带入 |
| 整页扫描图 | 默认保护 | 强提示，并要求逐页预览或限制处理范围 |
| 无关自动规则 | 仅按当前自动配置 | 完全禁用，不得旁路生效 |
| 成功标准 | 有效文档内容未受损 | 删除的是用户选定的目标及确认的同款 |

## 4. 现有功能与成熟度

| 功能 | 已实现部分 | 主要缺口 |
| --- | --- | --- |
| 插件初始化 | 握手、菜单和工具注册 | 初始化失败反馈、资源生命周期与卸载验证 |
| 自动清理 | 文本、路径、图片、链接、标准水印容器识别 | 默认规则过宽；缺少统一预览、备份和保护检查 |
| 人工点选 | 边界框命中、特征提取、全文计数、确认 | 目标定位不精确；内容身份不足；缺少候选可视复核 |
| 嵌套内容 | Form/Container 递归 | 点选链路、变换传递、计数与删除语义不一致 |
| 批处理 | 多选文件、逐文档处理、合计结果 | 保存参数、备份、逐文件异常隔离、配置传递 |
| 页面扫描 | 顶层元素计数、部分规则检测 | 嵌套对象漏统计；注解类型统计错误；不使用当前设置 |
| 设置 | 五项开关 | 配置不持久化；高级规则缺乏风险分级 |
| 备份 | 手动清理前尝试保存临时文件 | 非独立副本语义；不是所有入口都有备份；失败策略不足 |

## 5. 主要问题、影响及改进要求

本报告优先级定义：P0 为下一次发布前必须解决的数据保护或核心精准性问题；P1 为完整功能验收前必须解决的问题；P2 为工程完善项。该分级不表示问题已在所有文档中发生。

### R01：文本运行命中后删除整个文本对象（P0）

**证据：代码确认。** `WatermarkService.cpp:501` 起逐个检查 text run；`:383` 和 `:454` 附近在命中后调用 `PDEContentRemoveElem` 删除整个 `PDEText`。

**触发场景：** 一个文本对象同时包含正文和水印，或同时包含可见正文与隐形文字。其中一个 run 命中即可导致整个对象被删除。

**影响：** 删除范围超过识别范围，可能出现整段甚至大范围正文缺失。仅展示命中数量无法说明真实影响。

**改进要求：** 删除粒度必须与识别粒度一致。优先在 SDK 支持范围内定位并移除对应 run/字符区间；无法安全分离时，自动模式跳过，人工模式显示整个实际删除范围并要求明确选择。处理时保留非目标文字的字体、位置和绘制状态。

**验收：** 混合对象只移除目标；非目标文字的渲染、提取文本和布局保持一致。不能安全分离的对象不得自动整块删除。

### R02：默认清理不可见文字，缺少 OCR 保护（P0）

**证据：代码确认；对具体历史样例的影响待验证。** `WatermarkService.h:50` 默认开启透明文字删除；`WatermarkService.cpp:534` 起按填充透明度和 `renderMode == 3` 判定。

**影响：** 看不见的文字可能承担搜索、复制或阅读辅助功能。页面看起来不变，不代表文档没有受损。仅检查填充透明度还不足以判断使用描边等绘制方式的文本是否可见。

**改进要求：** 默认关闭此类独立删除规则。把不可见文字作为受保护内容；如未来提供独立的“清理隐藏内容”功能，应与水印清理明确分离，并解释其后果。标准水印对象包含必要关联内容时也应先评估依赖，不能只凭透明度删其子对象。

**验收：** 自动清理前后，普通扫描 OCR 文档仍可搜索和复制原有正文；不存在针对非目标 OCR 层的删除记录。

### R03：把所有链接注解视为推广链接（P0）

**证据：代码确认。** `WatermarkService.h:51` 默认开启链接删除；`WatermarkService.cpp:175` 起仅判断 `Subtype == Link`。

**影响：** 正常目录跳转、参考链接及业务链接均可能失效，且不一定产生可见变化。

**改进要求：** 默认不删除链接。若链接明确属于已确认的水印或广告，应建立其与目标的关联证据，作为单独候选展示。不得仅凭存在 URL、位于页脚或 Link 类型认定为推广。

**验收：** 普通链接、内部跳转保持有效；目标附带链接的删除必须出现在预览和执行清单中。

### R04：文本“精确匹配”存在确定性误匹配（P0）

**证据：代码确认，反例为静态推导。** `WatermarkService.cpp:130` 的 `FingerprintExactMatch` 对任意原始字节进行两字节分组，忽略最后一个孤立字节。

**反例：** `A` 与 `B` 均得到空序列，可能被判相等；`ABC` 与 `ABD` 均只保留 `AB`。这些反例尚未在宿主中执行，但可直接从循环边界推出。

**改进要求：** 禁止未经编码确认进行宽松 UTF-16 比较；原始字节相同也必须结合字体编码身份判断。优先通过字体映射获得可靠字符内容，不能映射时退回严格的字节及字体资源身份匹配。默认保留大小写、标点和空白差异，任何归一化规则都要有明确定义和测试。

**验收：** 单字节差异、奇数长度、不同编码映射及不同文本不再误匹配；目标文字相同但正文用途不同的候选不得未经复核默认删除。

### R05：图片、路径缺少内容身份；文本缺少必要辅助约束（P0）

**证据：代码确认。** `WatermarkService.cpp:640` 附近的路径判断主要使用尺寸、图案填充与位置；`:729` 起的图片判断主要使用像素尺寸及位置；文本匹配成功后没有使用共享位置约束。

**影响：** 相同尺寸的不同图片、相似边界的不同矢量图，或者正文中与水印相同的文字都可能被当成同款。

**改进要求：** 建立按对象类型区分的内容指纹，详见第 7 节。位置、尺寸和重复次数只能作为辅助证据。不能将跨页面相同对象编号直接当作跨文档身份。

**验收：** 不同内容同尺寸的图片和路径不匹配；同内容但变换不同的对象按用户选择的匹配模式处理；文本候选有内容、样式和位置等可解释信息。

### R06：容器点击未定位真实子目标，变换链未正确接入（P0）

**证据：代码确认。** `SelectionTool.cpp:360` 调用 `ExtractContainerFingerprint`。该方法从容器内倒序选择可识别子元素，不接收点击点；`HitTestFormContent` 只有定义和内部递归调用，没有接入实际点击入口。实际入口设置 `inForm = true`，但该路径没有记录对应的真实 Form 矩阵。

**影响：** 点击容器的一个区域，可能提取另一个子元素；容器边界、子对象边界和不同坐标空间混用，导致漏匹配或误匹配。

**改进要求：** 使用完整祖先变换链，把候选边界和点击坐标统一到同一坐标空间。不要直接启用旧函数就视为修复完成，旧函数的矩阵与边界约定仍须验证。边界框只用于初筛，文本应尽量定位到 run/字符，路径应进一步评估实际绘制区域；重叠时让用户切换候选。

**验收：** 平移、缩放、旋转、非零 CropBox 原点及多层 Form 下均选中实际点击对象。高亮范围与实际删除范围一致。

### R07：预览计数、实际删除与手动作用域不一致（P0）

**证据：代码确认。** `countContainer` 复用 `countPageContent`，但 `cleanContainer` 另写递归逻辑，没有相同的标准水印容器处理。普通手动模式在 `cleanPageContent` 中仍无条件移除顶层标准水印容器；标记水印专用模式又直接跳过其他容器，未向下寻找嵌套目标。

**影响：** 可能出现计数与执行不符、嵌套水印漏删、点选一个目标却删除其他标准水印等情况。标记相同也不代表内容属于同一款水印。

**改进要求：** 生成一次明确的删除计划，预览和执行共享该计划。手动模式只应用目标匹配规则；标准水印标记作为证据，不应成为绕过目标匹配的分支。

**验收：** 成功删除、跳过、失败三类结果之和与批准的计划条目相符；不会出现计划外删除。无文档变化且无执行错误时，实际删除范围与预览一致。

### R08：备份未覆盖所有入口，且缺少独立副本语义（P0）

**证据：代码确认及本地 SDK 说明。** `SelectionTool.cpp:485` 起仅在手动流程尝试备份，`:501` 使用 `PDSaveFull` 而未使用 `PDSaveCopy`。SDK 的 `PDExpT.h` 说明后者用于保存副本并让 PDDoc 继续关联旧文件。一键及批量入口没有同等备份流程。

**影响：** 临时文件可能成为当前文档的后续保存目标，不是可靠独立备份；部分备份准备失败分支会继续删除。批量模式会直接处理原文件，风险更集中。

**改进要求：** 三种入口统一使用已验证的独立备份机制。按 SDK 正确采用保存副本的标志与目标路径，保存当前内存状态；存在未保存编辑时不能简单复制磁盘原文件代替。备份创建、写入和基本验证失败时不进入删除。备份名称唯一、路径可查、保留策略明确。

**验收：** 备份成功且可打开，当前文档保存关联保持正确；删除后仍能恢复操作前状态。磁盘满、路径不可写或保存异常时，不产生部分清理。

### R09：批量保存参数、设置传递及异常隔离不足（P0）

**证据：代码确认及本地 SDK 说明。** `MenuHandler.cpp:381` 调用默认 `cleanDocument(doc)`，忽略 `gSettings`；`:385` 以 `PDSaveFull` 配合空目标路径保存，与本地 `PDProcs.h:1332` 起的接口说明不一致。相关流程未见 SDK 异常捕获。

**影响：** 用户关闭的规则仍可能在批量中生效；保存行为不可依赖；一个异常可能中断整个批次并绕过关闭与汇总。

**改进要求：** 批次开始时冻结配置快照，逐文件传入。正确处理原路径和副本路径，设置逐文档异常边界。默认输出新文件；明确选择覆盖时，必须先建立可恢复备份并验证保存结果。不能因打开返回非空就认定该文件处理成功。

**验收：** 相同配置下批量与单文件结果一致；故障文件单独报告，其余文件继续；成功统计以清理和保存均成功为准。

### R10：关键词编码识别错误，且规则证据不足（P1）

**证据：代码确认。** `WatermarkService.cpp:121`、`:594`、`:604` 使用 `find_first_not_of(" -~")`。该 API 把参数视为字符集合，而不是 ASCII 字符范围。关键词中还有“备注”“扫描”等普通词；关键词循环没有统一的字号或位置限制。

**影响：** 英文关键词可能走错误编码路径；中文普通词可能误伤正文。修复 ASCII 判断后会扩大原本漏检的关键词命中范围，若不同时收紧删除政策，可能增加误删。

**改进要求：** 编码与识别政策必须一并修改。不要假定 PDF 字形编码就是 GBK 或 UTF-16；优先使用可靠字体映射。关键词默认只产生建议，不独立授权自动删除。

**验收：** 英文、中文、子集字体、CID 编码均有正负样例；普通正文包含关键词时默认保留。禁止以“修复后删除更多”单独判定成功。

### R11：页面检查结果不准确（P1）

**证据：代码确认。** `WatermarkService.cpp:784` 将所有注解数赋给链接注解数；检查仅统计顶层对象。`MenuHandler.cpp:290` 新建默认选项，未使用当前设置。图案统计又受删除规则开关影响。

**改进要求：** 结构统计与规则命中分离。递归统计并明确顶层/子对象口径；按注解子类型计数；规则分析使用当前配置快照；显示实际命中原因。修复 UTF-8 字节直接构造宽字符串产生的中文展示问题。

**验收：** 不同注解类型和嵌套对象统计正确；切换规则只改变候选数量，不改变实际图元数量。

### R12：错误处理、资源管理和长任务体验不足（P1）

**证据：代码确认及待验证风险。** 页面、内容、路径等资源主要通过正常路径释放；缺少围绕 SDK 调用的统一异常边界。全文预览及删除同步循环执行，未提供明确的进度和取消策略。

**改进要求：** 按 SDK 异常机制设计清理路径，不能假设普通 C++ RAII 能覆盖所有 SDK 非局部跳转。明确资源所有权，检查内存分配和初始化失败。长任务增加进度、取消边界和执行状态；宿主 API 调用遵守线程约束，不能简单移到后台线程。

**验收：** 打开失败、权限限制、内容异常、保存失败及用户取消均能形成明确结果，资源被释放，不显示无条件“成功”。

### R13：构建、安装和版本不可复现（P1）

**证据：代码确认；现有构建失败已观察。** `build.ps1` 硬编码本机路径；安装脚本对宿主位数与文件复制失败的校验不足；PowerShell 安装以目标存在判成功可能把旧文件视为新安装成功。

**改进要求：** 使用脚本所在目录定位项目；探测工具链或接受明确参数；验证 SDK 路径、宿主位数和构建目标。安装应检查复制结果及源目标校验值，正确传递提权子进程退出码。统一版本来源，记录构建标识和受测宿主版本。

**验收：** 在无开发者专属路径的新环境可重复构建；目标文件被占用或复制失败时必须报告失败；安装版本可核对。

### R14：文档承诺超过实际能力（P1）

**证据：文档与代码对照确认。** README 将备份和预览描述为通用机制；SDK README 宣称 Mock 模式和环境变量入口，但构建未提供相应实现。README 版本记录、CMake 项目版本及“关于”窗口版本不一致。

**改进要求：** 修复完成后同步文档，明确每种模式的默认规则、保存行为和能力边界；删除“绝不误删”“无损”等未经验证的绝对措辞。未实现的模式应标注规划状态或移除说明。

**验收：** 文档中的安装、构建、配置和恢复步骤可以按步骤完成，界面与文档的版本和规则一致。

## 6. 自动清理的具体改进设计

### 6.1 默认规则建议

| 信号或对象 | 建议默认处理 | 理由与限制 |
| --- | --- | --- |
| 明确的标准水印标记 | 作为高置信候选，经过独立性和影响范围检查后纳入计划 | 标记是强证据，但不保证容器中所有内容均可安全删除 |
| RenderMode=3、Opacity≈0 | 保留 | 可能是 OCR 或其他有效隐藏内容 |
| Link 注解 | 保留 | 链接类型不能证明推广用途 |
| URL、品牌词、普通关键词 | 只报告疑似对象 | 正文也可能包含相同文字 |
| 底部通栏、贴底图片 | 保留，作为高级候选 | 可能是页脚、表格线、标识或有效图片 |
| Pattern 填充、大面积低透明度对象 | 保留，作为高级候选 | 可能是设计背景或图表内容 |
| 整页扫描图 | 保护 | 删除将导致页面正文缺失 |
| 跨页重复元素 | 仅增加证据 | 页眉、页脚、公司标识同样重复 |
| 无法正确解码或识别的对象 | 跳过并说明 | 不确定不能作为删除依据 |

### 6.2 建议操作流程

1. 检查文档可编辑性、当前状态和已启用规则，记录配置快照。
2. 只读扫描并生成删除计划，不立即修改对象。
3. 展示候选数量、涉及页面及简短原因；候选有可视定位。没有可靠候选时正常返回“未发现可自动删除对象”。
4. 展示影响提示，例如是否涉及复合容器或关联注解；不符合默认安全条件的条目不纳入自动计划。
5. 用户确认后建立并验证备份。
6. 复核文档未变化，执行已批准计划，记录实际结果。
7. 刷新页面并提供前后查看；标记需要保存，明确当前文件是否已写回磁盘。

建议普通自动入口保留一次简短范围确认。未来如要减少确认次数，应作为明确配置，且不得省略计划、保护和备份机制。

### 6.3 不可见变化必须可解释

报告不能只写“删除 N 处水印”。至少分开显示可视目标、关联对象和跳过对象。默认模式若没有修改不可见内容，应明确说明这一点；若某个已确认目标确需同时移除关联内容，应在操作前展示，不应到操作后才告知。

不能使用“渲染前后相同”证明安全，必须检查文本提取、搜索、链接和其他功能。对于用户反馈的历史异常，后续应先收集副本、清理前后文件、选项、日志及受影响页，再定位具体对象。

## 7. 人工点击删除同款的精准化设计

### 7.1 明确选择单位

可选择单位包括单个图像实例、文本 run/字符片段、路径对象，或用户明确选中的复合水印组。不要把包含目标的整个 Form 自动当作目标组。

首次点击应高亮实际目标。若存在多个重叠候选，允许循环切换或展示候选列表；透明对象、背景图和整页容器不能静默抢占目标。无法准确命中时应提示，而不是猜测后直接全文匹配。

### 7.2 按类型建立指纹

| 类型 | 核心身份依据 | 辅助信息 | 禁止单独作为同款依据 |
| --- | --- | --- | --- |
| 图片 | 同文档资源身份；或包含颜色空间、掩膜等信息的规范化内容指纹 | 位置、大小、旋转、透明度、裁剪 | 像素宽高相同 |
| 文本 | 可靠解码内容及编码/字体上下文 | 字体、字号、颜色、角度、位置、透明度 | 原始字节碰巧相同、截断后的 UTF-16 序列 |
| 路径 | 规范化几何指令、填充/描边及必要资源信息 | 变换、位置、尺寸 | 边界框相同或同为 Pattern |
| 复合组 | 明确选定的子对象集合、结构及相对布局 | 总边界、组变换、标记信息 | 都标记为 Watermark 或都属于同一容器类型 |

图片内容比较需考虑不同压缩方式、软掩膜、颜色空间和可见裁剪；仅比较压缩流哈希可能漏掉视觉相同对象，仅比较渲染外观又可能混淆不同语义对象。先实现严格资源/内容匹配，再将近似视觉匹配作为独立可选能力。

### 7.3 匹配范围与置信度

- 默认启用严格同款：内容身份明确，样式差异在已定义范围内。
- 位置相近可以作为默认辅助约束，但应允许用户查看相同内容出现在不同位置的候选。
- 提供明确的放宽项：允许位置变化、等比例缩放、旋转、样式变化。每次修改后重新生成计划。
- 低置信候选进入待复核列表，默认不选中。
- 支持当前页、页码范围、全文及逐候选排除。
- 共享 Form/XObject 的不同使用实例要分别核算影响。只删一个实例时，必要时隔离共享内容后修改，不能未经确认影响其他实例。

### 7.4 可视复核与恢复

建议显示选中目标的局部预览、全文候选分布及按页查看入口，候选标注与删除粒度保持一致。整页对象仍需高危提示，但二次确认不能替代正确匹配。

执行后提供前后切换或差异查看，并允许在保存前确认效果。若 SDK 支持可靠的撤销集成，应按宿主约定实现；否则以经过验证的备份恢复作为最低保障，界面不能宣称已有原生撤销。

### 7.5 高亮预览：明确采纳的交互要求

用户补充：当前版本命中后仅通过弹窗显示尺寸和位置，无法直观看到选中了什么。高亮预览应作为人工删除模式的核心要求，不能只保留为后续可选优化。

**第一步：点击后先展示目标，不立即删除。** 在页面原位置高亮实际选中对象，同时提供带周边正文的局部放大预览。尺寸、类型和位置作为辅助说明。若有多个重叠对象，提供“上一个／下一个目标”，切换时同步更新高亮和局部预览。用户确认目标正确后，再查找全文候选。

**第二步：展示全文候选。** 优先查找同一底层资源的使用实例，再查找独立复制的同款；两种来源应有简短标签，便于理解匹配依据。界面展示涉及页数和候选数，支持上一处、下一处及按页跳转。每个候选都有带上下文的预览，可以单独排除，也可以排除整页。低置信候选默认不选中。

**第三步：确认的是当前勾选集合。** 执行按钮显示明确的对象数及页面数，例如“删除已选 12 处，涉及 10 页”。被排除的候选不得再因重新扫描自动纳入删除。用户修改匹配条件后应重新生成并复核计划；文档在预览期间发生变化时旧计划失效。

高亮的表现与范围要求：

- 使用清晰轮廓或不遮挡内容的半透明覆盖，并配合文字标签，不能只靠颜色区分目标、已选候选和未选候选。
- 高亮应对应实际拟删除的对象、文字片段或复合组；不能高亮小水印，却实际删除其整页父容器。
- 对稀疏路径、透明图片和带裁剪的对象，仅画边界框仍可能误导，应结合对象外观或局部预览说明范围。复合组应显示其成员和整体影响范围。
- 命中整页时明确显示整页范围，不得用局部截图掩盖；无法进一步确定用户点击的小目标时停止，不自动退回整页删除。
- 高亮必须是临时显示，不作为注解、图形或其他持久对象写入 PDF；取消、退出工具或关闭文档后清除。
- 翻页、缩放、旋转和滚动后，高亮仍须与目标对齐。显示方式及可用 API 需通过 SDK 和宿主原型验证，不在本报告中假定已实现。

建议交互采用允许查看页面的预览面板，避免连续模态弹窗遮挡目标。最小交付应包含：当前目标高亮、候选逐项导航、逐项排除、明确数量确认和取消无修改。前后对比可随后增强；若提供删除效果模拟，必须在隔离副本或临时渲染中完成，不能为了生成预览先修改当前原文档。

验收补充：用户不需要理解点数、坐标或对象编号，也能明确指出当前选中的目标；高亮与执行清单一致；排除项保持不变；取消不改变文档内容或保存状态；整页误命中不能绕过目标复核。

## 8. 统一删除计划与执行架构

建议沿用现有模块边界，逐步抽出以下职责，避免一次性重写整个插件。

1. **对象遍历层**：统一递归，输出类型、页面、祖先路径、坐标变换和可编辑粒度；为异常循环或过深嵌套设置保护。
2. **判定层**：分为自动规则和人工目标匹配两套策略，不相互旁路调用。
3. **删除计划层**：记录候选、理由、范围、保护状态及用户选择；扫描不修改文档。
4. **执行层**：只执行已批准计划，验证前置条件，逐条记录结果。
5. **备份与保存层**：封装独立备份、保存、失败处理和恢复信息，供所有入口复用。

计划条目至少包含：文档身份及状态标记、页面、对象类型、祖先定位路径、必要的内容校验信息、世界/页面坐标下的边界、删除粒度、命中理由、置信等级、关联影响和批准状态。

不能只记录原始 PDE 指针或易变化的元素下标，并跨释放、保存或结构修改继续使用。执行前应重新定位并校验；同一容器内的索引变动和祖先/子对象重复删除必须处理。不要把运行时指针保存到日志后当作可恢复身份。

若预览后文档被编辑、切换或关闭，计划应失效。执行必须绑定原文档，不能再次查询“当前活动文档”就继续操作。

部分失败时不能显示整体成功。应报告已删除、未执行和失败项；若需要回滚，应使用验证过的恢复路径，不宣称现有 SDK 操作天然具有事务性。

## 9. 保存、备份与批处理规范

### 9.1 单文档

- 删除前备份当前编辑状态，包括尚未保存的合法编辑。
- 备份应保持当前文档与原文件的关联，不把临时副本变成用户继续编辑的目标。
- 备份成功后再修改；失败则停止本次清理并说明原因。
- 默认不立即覆盖磁盘原文件，由用户检查后保存。
- 界面准确区分“内容已修改”“备份已创建”“已写入文件”，不要混用。
- 恢复时应提醒保存之后新增的用户编辑可能需要另行保留。

### 9.2 批处理

- 默认输出到明确目录，避免与输入同名覆盖；用户可以明确选择覆盖模式。
- 覆盖模式逐文件备份，且备份可通过任务报告找到。
- 一次批次使用一份冻结的配置；报告记录配置版本。
- 逐文件独立处理错误，记录打开、扫描、备份、清理、保存、验证各阶段状态。
- 提供进度和取消。取消时不继续处理新文件，清楚列出已完成、当前文件及未处理文件。
- 对重复输入、同一文件已在宿主打开、输出路径冲突和加密文档建立明确策略。
- 保存失败不能被计入成功；不要仅以 `totalRemoved > 0` 代表结果正确。

### 9.3 备份与日志保留

临时目录可能被系统清理，不宜作为唯一的长期恢复承诺。建议提供可配置备份目录，记录源文件、时间、版本和清理会话标识。自动清理旧备份应有明确保留策略，不在用户不知情时删除唯一恢复副本。

日志默认记录对象类别、位置、原因、数量和错误，不记录完整正文或图片数据。需要诊断内容时使用用户主动启用的诊断模式。

## 11. 测试矩阵与验收方法

### 11.1 必备回归样例

| 编号 | 样例 | 自动模式预期 | 人工模式预期 |
| --- | --- | --- | --- |
| T01 | 无水印的普通文本 PDF | 零非目标删除 | 不应产生无关同款候选 |
| T02 | 扫描图加 OCR 隐形文字 | OCR 保留，搜索复制正常 | 点图不能隐式删除文字层 |
| T03 | 目录跳转、引用链接及普通网址 | 链接保留 | 只处理用户明确选定的目标 |
| T04 | 正文和水印共用 PDEText | 无法安全分离时跳过 | 只删指定 run/片段或明确告知不可分离 |
| T05 | 单字节、奇数长度文本 | 不错误判同款 | A/B、ABC/ABD 等不匹配 |
| T06 | 不同字体映射的相同原始字节 | 不直接按字节删 | 正确区分字符身份 |
| T07 | 同像素尺寸的不同图片 | 不凭尺寸删除 | 不同图像不匹配 |
| T08 | 同图片在不同位置/缩放/旋转出现 | 不凭重复自动删除 | 按用户选择的范围匹配 |
| T09 | 相同边界框的不同路径 | 保留普通图形 | 依照路径内容区分 |
| T10 | 多层 Form、旋转和裁剪 | 只处理可靠独立目标 | 点击、高亮、匹配和删除坐标一致 |
| T11 | 非零 CropBox 原点、混合页面尺寸 | 不因归一化错误产生误判 | 相对位置正确 |
| T12 | 顶层和嵌套标准水印容器 | 计划与执行一致 | 点选一种不顺带删除另一种 |
| T13 | 整页扫描图、页眉标识、表格底纹 | 默认保护 | 明确高危范围与候选差异 |
| T14 | 共享 Form/XObject 多次使用 | 评估共享影响后处理 | 限定实例不影响未选实例 |
| T15 | 透明填充但可见描边的文本 | 不因填充透明而误删 | 可视目标识别正确 |
| T16 | 预览后用户修改或切换文档 | 计划失效 | 不修改新活动文档 |
| T17 | 无写权限、磁盘满、备份失败 | 删除不开始 | 删除不开始 |

| T22 | 水印与正文融合在扫描图像中 | 不删整页图 | 明确能力边界，不宣称精准分离 |

### 11.2 验证不能只靠截图

每个重点样例至少进行以下检查：

1. 渲染前后对比：目标区域确有预期变化，非目标区域没有解释不了的变化。
2. 文本与功能对比：非目标文本提取、搜索、复制，以及链接目标和跳转功能保持一致。
3. 结构与范围对比：计划条目、实际修改对象和结果报告一致；必要时检查表单、批注、图层等。
4. 保存后验证：重新打开输出文件，再进行上述关键检查。
5. 恢复验证：从备份恢复后，文档状态对应操作前，不只是“备份文件存在”。

PDF 保存可能改变对象编号、压缩方式或文件字节，因此不能要求输出与输入二进制相同来判断非目标内容保持，也不能只依据文件大小变化判断成功。

### 11.3 建议的发布门槛

- 所有 P0 问题关闭，并有对应测试证据。
- 核心回归样例中非目标删除数为零；这是一条测试门槛，不是对任意 PDF 的绝对保证。
- 无异常执行时，计划与实际删除范围完全一致；发生跳过或失败时有逐项解释。
- 自动模式在 OCR、链接、普通关键词、整页扫描图等负样例上不产生误删。
- 人工模式的严格匹配在测试集中没有不同内容误匹配；支持范围内的同款变换样例能被正确发现。
- 备份失败阻断、保存失败反馈和恢复测试全部通过。
- 在明确列出的 Acrobat 与 Windows 环境中完成宿主集成验证，记录实际版本，不虚构兼容范围。
- 构建来源、插件版本、文档版本可追溯一致。

后续统计人工匹配准确率时，应分别统计误匹配和漏匹配；自动模式则优先统计非目标删除、不可见功能损失及无法解释的修改，不能只统计清理对象数量。

## 12. 分阶段实施路线

### 阶段 A：止损与保存可靠性

范围：R01、R02、R03、R04、R08、R09，以及 R07 中的手动规则越界。

交付物：安全默认规则、严格文本匹配、所有入口的备份机制、正确保存参数、批量配置和逐文件错误处理、核心反例测试。

退出条件：不会因默认隐形文字/链接规则静默破坏文档；不存在已知的单字符误匹配；备份失败不执行删除；手动模式不删除无关目标。

### 阶段 B：统一计划和遍历

范围：R06、R07、R11、R12 的核心结构。

交付物：统一对象遍历与变换上下文、删除计划、文档状态校验、准确扫描结果和逐条结果记录。

退出条件：嵌套、旋转、共享对象样例通过；预览与执行一致；错误不会被包装为成功。

### 阶段 C：人工精准匹配与复核

范围：R05、R06 的完整目标定位及交互。

交付物：分类型内容指纹、目标高亮、重叠候选选择、严格/扩展匹配、逐候选排除、前后检查与恢复入口。

退出条件：人工可以明确看见自己选择和即将删除的对象；支持范围内的同款能匹配，非同款不默认纳入计划。

### 阶段 D：自动识别和工程完善

范围：R10、R13、R14，以及性能、持久化设置与更广样例。

交付物：保守自动识别策略、可复现构建、可靠安装、配置持久化、正式用户文档和测试报告。

退出条件：默认自动模式符合第 2 节原则；文档与实现一致；通过完整发布门槛。

阶段之间可按实际依赖调整，但不能先放宽识别规则，再补数据保护。暂不提供日历工期：需先恢复构建环境、建立样例基线并验证宿主 SDK 的编辑与撤销能力，才能可靠估算。
